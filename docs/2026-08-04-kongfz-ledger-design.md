# 孔夫子查价 · 记账功能 设计方案

> 日期：2026-08-04
> 需求来源：用户记账场景——记录每日进货和成本盈利，以及每周/每月汇总

---

## 一、现状

现有功能：查价、加购、历史记录、快递追踪、地址管理、Cookie 管理。**没有任何记账能力。**

技术底座：
- 后端 `app.py`（Python http.server），数据以 JSON 文件存 `data/` 目录（如历史记录）
- 前端两个独立文件：`kongfz_web.html`（本地版）、`kongfz_cloud/index.html`（云版），**必须同步修改**
- 部署：改完推送 Railway，用户执行 `railway redeploy`

## 二、需求确认（已与用户澄清）

1. **按单记**：进货单 / 卖出单，一单一种书（可多本）
2. **盈利 = 卖价 − 进价**：卖出时手填成本，只算差价，不含佣金/运费
3. **汇总**：每日 / 每周 / 每月 的进货成本、销售额、盈利

## 三、详细设计

### 3.1 架构总览

```
前端（本地版 + 云版）
    │
    ├─ 📒 账本卡片（底部导航进入）
    │     ├─ 快速录入：进货 / 卖出 表单
    │     ├─ 汇总区：今日 / 本周 / 本月
    │     ├─ 每周每月滚动汇总（切换查看）
    │     └─ 明细列表 + 删除
    │
    └─ /api/ledger/* ──→ app.py 后端 ──→ data/kongfz_ledger.json
```

### 3.2 数据结构（单条记录）

**进货单（type=in）：**
```json
{
  "id": "IN_001",
  "type": "in",
  "book": "红岩",
  "isbn": "9787020002207",
  "qty": 10,
  "unit": 5.0,          // 每本进价
  "cost": 50.0,         // qty × unit，自动计算
  "date": "2026-08-04", // 用户可选日期，默认今天
  "created_at": "2026-08-04 10:00:00"
}
```

**卖出单（type=out）：**
```json
{
  "id": "OUT_001",
  "type": "out",
  "book": "红岩",
  "isbn": "9787020002207",
  "qty": 3,
  "unit": 15.0,         // 每本售价
  "cost": 5.0,          // 每本成本（手填）
  "sale": 45.0,         // qty × unit，自动计算
  "profit": 30.0,       // sale − (qty × cost)，自动计算
  "date": "2026-08-04",
  "created_at": "2026-08-04 10:30:00"
}
```

**盈利口径**：`盈利 = 数量 × 售价 − 数量 × 成本`（只算差价）

### 3.3 后端 API

| 接口 | 方法 | 参数 | 说明 |
|------|------|------|------|
| `/api/ledger/add` | POST | `type, book, isbn, qty, unit, cost, date` | 记一笔（进/销） |
| `/api/ledger/list` | GET | `limit, type` | 明细列表，按日期倒序 |
| `/api/ledger/summary` | GET | `scope=today\|week\|month` | 汇总 |
| `/api/ledger/delete` | GET | `id` | 删除一笔 |

**数据文件**：`data/kongfz_ledger.json`
```json
{ "records": [ ... ] }
```
存储逻辑复用现有历史记录模式（`load_history` / `save_history`），记录上限 500 条防膨胀。

**汇总逻辑：**
- `scope=today`：取 date == 今天
- `scope=week`：本周一 ~ 今天
- `scope=month`：本月 1 号 ~ 今天
- 返回：`{ in_cost, out_sale, profit, in_count, out_count }`

**每周每月滚动汇总（`/api/ledger/summary?scope=all`）**：
- 按自然周（周一为一周开始）、自然月分组
- 返回最近 8 周、最近 6 个月的聚合数组，供前端表格展示

### 3.4 前端界面

**入口**：底部导航新增「📒 账本」按钮（第 6 个），点击 `scrollTo` 到账本卡片并展开。

**账本卡片（`id="ledger"`）**，包含 4 块：

1. **快速录入**
   - 类型切换：进货 / 卖出（`type`）
   - 表单字段：
     - 书名 `input`（必填）
     - ISBN `input`（选填）
     - 数量 `number`（默认 1）
     - 单价 `number`（进货=进价 / 卖出=售价）
     - 成本 `number`（仅卖出显示，手填）
     - 日期 `input type=date`（默认今天）
   - 「保存」按钮 → POST `/api/ledger/add` → 刷新汇总+明细

2. **汇总区**（3 个 stat 卡片）
   - 今日：进货成本 / 销售额 / 盈利
   - 本周 / 本月（可切换 tab）

3. **每周每月**（切换"按周 / 按月"）
   - 表格：周期 | 进货成本 | 销售额 | 盈利
   - 周：最近 8 周；月：最近 6 个月

4. **明细列表**
   - 最近 20 条，按日期倒序
   - 每行：类型图标（进⬇/卖⬆）、书名、数量、金额、日期、删除按钮
   - 卖出单显示盈利金额（绿色正/红色负）

### 3.5 涉及文件

| 文件 | 改动 |
|------|------|
| `kongfz_cloud/app.py` | 新增 4 个 `/api/ledger/*` 路由 + 存取函数 |
| `kongfz_cloud/index.html` | 云版前端：底部导航 + 账本卡片 |
| `kongfz_web.html` | 本地版前端：同 index.html 同步改 |
| `data/kongfz_ledger.json` | 运行时自动生成 |

> 提醒：本地版与云版前端必须同步改（见记忆 kongfz-sync-both-frontends）。

## 四、边界情况与错误处理

| 场景 | 处理方式 |
|------|---------|
| 必填字段缺失（书名/数量/单价） | 前端提示，后端校验返回 error |
| 成本未填（卖出） | 提示补填，不允许保存 |
| 数量 ≤ 0 或单价 ≤ 0 | 后端校验，拒绝 |
| 数据文件损坏 | `load` 失败时重置为空，不崩溃 |
| 删除不存在记录 | 返回 success 忽略 |
| 明细超过 500 条 | 保留最近 500，丢弃最旧 |

## 五、不做（YAGNI）

- 库存扣减 / 自动计算剩余库存（用户选按单记，不管理库存）
- 平台佣金、运费等费用项（用户明确只要差价）
- 成本自动从进货记录带出（用户明确手填）
- 进货单 ↔ 卖出单关联
- 图表可视化
- 多用户 / 登录体系（单用户个人工具）
